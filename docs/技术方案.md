## 1. 总体架构

### 1.1 分层原则（对齐工作区现有游戏）

```
┌─────────────────────────────────────────────┐
│ pages（Vue 页面）  index / game / settings   │
├─────────────────────────────────────────────┤
│ composables（组合式封装） useGame / history   │
│              / useSound；reactive 视图 + AI 调度│
├─────────────────────────────────────────────┤
│ core（纯 JS，平台无关，可单测）                │
│  cards / rules / game / ai / settings         │
├─────────────────────────────────────────────┤
│ 存储（uni.storage）  本地持久化，key 前缀隔离  │
└─────────────────────────────────────────────┘
```

- **core 层不依赖 Vue、不依赖 `uni` API**：所有规则判定、状态流转、AI 决策都是纯函数/纯状态对象，Vitest 在 node 环境直接覆盖。
- **composable 层**把 core 状态包成 Vue `reactive` 视图，负责回合节奏（延时）、AI 自动行动、持久化读写、音效触发。
- **页面层**只做渲染与交互转发，不写规则判定；合法性一律以 core 返回的 `{ ok, reason }` 为准。

## 2. 核心数据模型

### 2.1 牌对象（cards.js）

```ts
type Suit = 'spade' | 'heart' | 'club' | 'diamond'
type Rank = 'A'|'2'|...|'10'|'J'|'Q'|'K'|'SJ'|'BJ'

interface Card {
  id: string          // 唯一：'spade-A' / 'joker-SJ'
  rank: Rank
  suit: Suit | null
  color: 'red' | 'black'
  joker: 'SJ' | 'BJ' | null
  label: string       // 展示文案：A / 10 / 小王 …
  suitLabel: string   // ♠ ♥ ♣ ♦，王为 ''
}
```

构造：`buildDeck()` 返回 54 张；`shuffle(cards, rng)`  Fisher–Yates 返回新数组；`mulberry32(seed)` 种子随机数（测试复现用）。

### 2.2 对局状态（game.js）

```ts
interface Slot {
  card: Card
  faceUp: boolean
}

interface PlayerState {
  seat: number
  hand: Card[]
  collected: Card[]      // 收集堆
  interferenceUsed: number
  memory: Map<number, MemoryEntry>  // 仅 AI 使用；视图层不下发
}

interface MemoryEntry {
  rank: Rank
  confidence: number
  knownAt: number       // 回合序号，便于清理过期记忆
}

type Phase = 'DEAL' | 'PLAYING' | 'SETTLE'

interface GameState {
  rng: () => number
  state: Phase
  playerCount: 2 | 3 | 4
  settings: NormalizedSettings
  array: (Slot | null)[]      // 长度 12，null = 空位
  drawPile: Card[]
  discard: Card[]
  players: PlayerState[]
  currentSeat: number
  turnNo: number
  pending: {                  // 翻牌进行态
    first: number | null
    second: number | null
    stage: 'idle' | 'picked' | 'revealed'
  }
  history: HistoryEntry[]
  result: Settlement | null
}
```

### 2.3 历史条目（history entry）

```ts
interface HistoryEntry {
  seat: number
  action: 'flip' | 'replace' | 'peek' | 'swap' | 'skip'
  slots?: number[]            // 涉及槽位
  handCardId?: string
  ok: boolean
  detail?: string
  turnNo: number
}
```

## 3. 状态机设计

### 3.1 阶段流转

```
DEAL ──startGame(g)──▶ PLAYING ──结束条件满足──▶ SETTLE
                         ▲  │
                         │  └─ 每行动作后 endTurn 轮转下一座位
```

- `DEAL`：仅初始化阶段，发牌完成即进入 `PLAYING`。
- `PLAYING`：正常行动；`pending` 记录翻牌进行态。
- `SETTLE`：结算结果写入 `result`，不再接受行动。

### 3.2 core 公开接口（game.js）

所有行动函数签名：`(g, seat, ...args) => { ok: boolean, reason?: string }`；非法动作不改状态。

| 函数 | 职责 |
| --- | --- |
| `createGame(rng, settings)` | 构造空状态（DEAL） |
| `startGame(g, playerCount)` | 洗牌、入阵 12、发手牌 4、剩余入抽牌堆，进入 PLAYING |
| `flipCard(g, seat, slot)` | 翻第一张/第二张；第二张翻开后不立即结算，交由 `resolvePair`；第一张若与阵中亮牌同点数，直接把亮牌当第一张、本张当第二张并置 `stage='revealed'`，返回 `claimSlot` |
| `cancelPending(g)` | 撤销本回合已翻开的牌并清空 pending（AI 翻牌凑不到第二张时的兜底） |
| `resolvePair(g)` | 比对本回合两张：成功收走 / 失败标记待盖回；返回结果描述 |
| `coverMismatch(g)` | 把失败的两张盖回原位（UI 延时后调用） |
| `shiftCard(g, seat, handCardId, targetSlot, mode='loud')` | 回声移位干扰：mode 为 `loud`（明投，正面入阵）/ `mute`（暗投，背面入阵）；原牌退回抽牌堆底或弃牌堆；返回 `{ ok, mode, displaced }` |
| `peekCard(g, seat, handCardId, slot)` | 小王窥视 |
| `swapJoker(g, seat, handCardId, targetSlot, emptySlot?)` | 大王强换 |
| `skipTurn(g, seat)` | 无合法行动时跳过 |
| `endTurn(g)` | 补手牌、补阵面、推进座位、检查结束条件 |
| `viewOf(g, viewerSeat)` | 脱敏视图（见 §3.5） |

### 3.3 翻牌时序（核心状态 + UI 节奏）

1. 玩家点槽位 → `flipCard`：`stage='picked'`，记录 `first`。
2. 点第二张 → `flipCard`：`stage='revealed'`，记录 `second`。
3. composable 延时后调 `resolvePair`：
   - 成功：两槽置 `null`，牌入收集堆，写历史，触发阵面补给检查。
   - 失败：保留正面，延时后调 `coverMismatch` 盖回。
4. 比对完成后 `endTurn` 轮转。

> 核心层不做 `setTimeout`；节奏由 composable 编排，保证 core 可在测试中同步调用。

### 3.4 补给与结束判定（rules.js / game.js）

- `refillHands(g)`：回合末逐张补手牌至 4。
- `refillArray(g, batchSize=4)`：空位优先补，每批 ≤ 4 张背面牌。
- `isGameOver(g)`：`array.every(s => s === null) && drawPile.length === 0`。
- `settle(players)`：按收集张数 → 配对对数 → 平局破平，产出 `{ winner, ranks, scores }`。

### 3.5 脱敏视图（viewOf）

```ts
viewOf(g, viewerSeat) = {
  state, playerCount, currentSeat, turnNo,
  array: g.array.map(s => s ? { slot, faceUp, card: s.faceUp ? s.card : null } : null),
  drawCount: g.drawPile.length,
  myHand: players[viewerSeat].hand,
  myCollected: players[viewerSeat].collected,
  myInterferenceUsed,
  opponents: players.filter(p => p.seat !== viewerSeat)
    .map(p => ({ seat, handCount: p.hand.length, collectedCount: p.collected.length, interferenceUsed: p.interferenceUsed })),
  pending: g.pending,
  history: g.history,
  result: g.result,
  settings: { ...g.settings },
}
```

- 他人手牌内容、AI `memory` 一律不下发；背面牌的 `card` 置 null，避免前端越权读到牌面。

## 4. 规则纯函数（rules.js）

| 函数 | 职责 |
| --- | --- |
| `isPair(cardA, cardB)` | 两普通牌且 rank 相同；王牌返回 false |
| `isJoker(card)` | 判断 SJ/BJ |
| `legalReplaceTargets(g, seat)` | 可被替换的正面槽位 + 可用空位 + 可出手牌 |
| `legalPeekTargets(g, seat)` | 可窥视的背面槽位 |
| `countPairs(collected)` | 收集堆中成对数量（按 rank 两两计数） |
| `settle(players)` | 排序、名次、积分（口径见需求 §7.3） |
| `scoreFor(rankIndex, playerCount)` | 名次积分表查询 |

规则集中在 rules.js，game.js 只做状态流转与参数校验，便于单测覆盖边界。

## 5. AI 设计（ai.js）

### 5.1 参数表

```ts
const DIFFICULTY = {
  easy:   { memoryAccuracy: 0.55, recallAccuracy: 0.50, interferenceRate: 0.15, peekRate: 0.30, thinkDelay: [1600, 2400] },
  normal: { memoryAccuracy: 0.80, recallAccuracy: 0.75, interferenceRate: 0.30, peekRate: 0.50, thinkDelay: [1200, 1900] },
  hard:   { memoryAccuracy: 0.95, recallAccuracy: 0.92, interferenceRate: 0.45, peekRate: 0.70, thinkDelay: [900, 1500] },
}
```

### 5.2 记忆入账接口（供 game.js 调用）

| 函数 | 职责 |
| --- | --- |
| `observePublic(g, slot, card, bySeat)` | 公开亮牌：除被窥视场景外，所有 AI 按 memoryAccuracy 入账 |
| `observePrivate(g, seat, slot, card)` | 窥视入账：仅写入该 AI 记忆，满置信 |
| `forgetSlot(g, slot)` | 槽位被替换/盖回时，清除所有 AI 该槽记忆 |
| `rememberedPair(g, seat)` | 召回：记忆中两张同点槽位（按 recallAccuracy 抽检） |

### 5.3 决策输出

`aiChooseAction(g, seat)` 返回：

```ts
| { action: 'flip', slots: [number, number] }
| { action: 'replace', handCardId, targetSlot, mode }
| { action: 'peek', handCardId, slot }
| { action: 'swap', handCardId, targetSlot, emptySlot? }
| { action: 'skip' }
```

决策顺序见需求 §8.3；AI 只读取 core 状态与自身 memory，不触碰视图层。

### 5.4 AI 调度（useGame.js）

- `scheduleAiIfNeeded()`：当前座位为 AI 时，按难度 `thinkDelay` 区间延时；到点重新校验 `state/currentSeat` 防止过期定时器，再调 `aiChooseAction` 执行对应 core 接口。
- 行动后 `syncView()` → 继续调度下一位；进入 SETTLE 后写战绩与历史。

## 7. 组合式与页面

### 7.1 useGame.js

职责：

- 初始化 `createGame` + `startGame`，包成 `reactive(view)`。
- 暴露：`view / fx / myTurn / interferenceLeft / labelOf` 与真人行动方法 `selectHand / cancelMode / onArrayTap / submitShift / skipTurnHuman / restart`。
- `syncView()`：从 `viewOf(g, 0)` 重建视图数组（浅拷贝保证 Vue 响应式感知）。
- AI 调度、结算持久化（stats + history）、静音读取。
- `fx` 附属交互态：`mode`、`selectedHandId`、`targetSlot`、`settleShow`、`thinking`、`peekCard`、`announcements`、`collectFx`、`shiftFx`、`busy`；`submitShift(mode)` 为替换模式第二步（`loud` / `mute`）。

### 7.2 页面职责

**index.vue**：菜单（开始 / 设置）、战绩摘要（局数、胜场、总收集）、规则弹层入口；`onShow` 刷新本地数据。

**game.vue**：
- 顶部 `SeatBadge` 列表（AI 座位 + 我自己的回合标识）。
- 中部 3×4 阵面：`ArrayCard` 网格；背面/正面/空位三态；点击按当前模式路由到翻牌、回声移位选目标、窥视或强换。
- 底部 `HandCard` 列表：普通牌可选中进干扰模式；小王/大王点击直接进入对应行动选择。
- 状态提示：当前回合、剩余干扰次数、抽牌堆张数、错误 toast。
- 结算浮层 `SettleList`：名次、收集张数、配对对数、积分；再来一局 / 返回菜单。

**settings.vue**：人数单选（2/3/4）、难度三档、干扰上限步进（1–5）、静音开关；点选即存。

## 12. 关键边界与防错清单

1. **守恒**：收牌、替换、窥视、强换、补牌、弃牌各路径断言 54 张不丢不重。
2. **背面信息隔离**：视图层背面牌不带 `card`；AI memory 不下发；窥视特写不写入公开历史。
3. **替换空位**：普通替换必须有空位；大王强换无空位时原牌进弃牌堆。
4. **干扰上限**：达到 `interferenceLimit` 后行动 B 拒绝；王牌不计次。
5. **过期定时器**：AI 延时回调前重校 `state === 'PLAYING' && currentSeat === seat`。
6. **翻牌连击**：`pending.stage` 未到 `idle` 前拒绝新的翻牌选择。
7. **牌组耗尽**：抽牌堆空后补给静默跳过；结束判定不依赖手牌/弃牌/收集堆。
8. **存储容错**：所有 storage 读写 try-catch，坏数据走 `normalizeSettings` 回退默认。
